# 文案与用词（VOICE）

本文件约束「消费者主线」上的一切可见文案。目的是把**档案文献腔**换成**货架前的人话**，
同时不越过 `AGENTS.md` 的零推断红线：可以换说法，不可以加判断。

适用范围：

| 范围 | 是否受本文件约束 |
| --- | --- |
| `apps/web/src/pages/ScanPage.tsx`（消费者主线） | 是 |
| `apps/web/src/App.tsx` 页眉、页签、页脚 | 是（页脚运行状态字段除外） |
| `apps/web/src/pages/DietPage.tsx` | 是 |
| `apps/web/src/pages/DossierPage.tsx`（审计视图） | 否：审计视图保留 `evidence_id`、`payload_sha256`、覆盖状态枚举与 16 区块编号 |

## 一句话原则

> 说的是「你扫的这包东西」，不是「本页所展示之数据」。

- 用第二人称与平实动词：`你扫的`、`包装上写的是`、`看看`。
- 先说结论位置，再说依据：先给「这是什么 / 里面有什么 / 谁做的」，出处放在每段末尾。
- 免责不消失，但要说成人话：**不做评价、不做推断**的实质必须保留。

## 术语替换表（旧 → 新）

消费者主线一律用右列；左列只允许出现在审计视图（`DossierPage`）、
折叠展开后的追溯披露（`TraceDisclosure`）与代码/数据字段中。

| 旧（公文 / 数据库语义） | 新（消费者主线） | 说明 |
| --- | --- | --- |
| 检索公开档案 | 看看是什么 | 主按钮；不出现「检索 / 查询 / 拉取」 |
| 按条码检索公开档案 | 扫码，看这包东西 | 入口标题 |
| 输入条码（如 6901234567892） | 条码数字，例如 6901234567892 | 占位符；仍是同一输入框 |
| 数据分片 / 静态分片 | 公开记录 | 分片是构建机概念，消费者不需要 |
| 16 区块档案与来源 | 原始记录与出处 | 页签与跳转入口 |
| 查看 16 区块档案与来源追溯 → | 看原始记录与出处 → | 跳转审计视图的入口 |
| 区块（01–16） | 栏目 / 段落 | 消费者视图不出现「区块」，编号也不出现 |
| 观测 / 多源观测并列 | 每个来源各自的原话 | 强调并列，但不用「观测」 |
| 并列呈现 / 仅做并列呈现 | 分别列出，不合成一条 | 保留「不合并」的语义 |
| 证据 / 证据绑定 | 原文 / 原文编号 | 消费者视图只说「原文」 |
| 追溯 / 追溯视图 | 出处 / 原始记录 | 不说「追溯」 |
| 可见性事件 | （不出现） | 只在审计视图 |
| query_status / QUERIED_MATCHED | 这次查到了记录 | 状态用一句话，不显示枚举 |
| query_status / QUERIED_NO_MATCH | 没有找到这条条码的记录 | 并补「这不代表任何结论」 |
| evidence_id | 原文编号 | **不翻译**；消费者视图不显示，审计视图显示全值 |
| payload_sha256 | 内容摘要（哈希） | 只在审计视图折叠区内显示全值 |
| 实体 / entity_id | （不出现） | 只在审计视图 |
| 候选 / 候选条数 | 还有别的说法 | 段标题；候选关系用一句话说明 |
| 手动确认 / MANUAL_CONFIRM | 需要你自己确认 | 保留「不替你合并」的语义 |
| 精确命中 / EXACT_IDENTIFIER_MATCH | 条码完全一致 | 同上 |
| 机械对照 / 词条机械匹配 | 字面比对 | 「你写的词出现在包装文字里，就列出来」 |
| 本页 / 该数据 / 本档案 | 这里 / 这条信息 | 去官腔 |
| 不构成任何结论 | 我们不下结论 | 保留实质 |
| 演示样例（说明句里的「分片」） | 演示样例（说明句里的「真实商品库记录」） | 「演示样例」四个字本身不得改动 |

### 替换时必须保留的东西

1. **来源并列**：多来源给出不同值时，一律逐条列出并标注来源名，不得合成一条、不得取「最可信」。
2. **演示样例标记**：`data-demo-mark` / `data-demo-scope` 属性与「演示样例」四个字不得删除或改写。
3. **不做判断的实质**：每段免责都必须仍能读出「不评价、不推断、不给建议」。
4. **关系与状态**：`link_mode`、覆盖状态这些机器可读值不得凭空消失——消费者主线用
   `data-link-mode`、`data-coverage-state` 等属性承载，审计视图照旧显示原始枚举。

## 禁用的替换方向

替换后的词**不得**引入推断意味。以下词一律不得出现在新增文案里（与
`packages/semantic_gate` 的禁用词表同向，且该表不得因本次改版放宽）：

`真伪`、`可靠`、`风险`、`建议`（作为结论给出时）、`推荐`、`安全`、`优质`、
`同源`、`换壳`、`合格`、`不合格`、`值得买`、`踩雷`。

正确的替代是**描述性**的：说「条码完全一致」「只有许可号，条码对不上」，
而不是「这条更可信」。

## 排版配套规则

| 规则 | 具体做法 |
| --- | --- |
| 衬线体只留给主标题与商品名 | `.serif` 只出现在 `App` 的 `h1` 与消费者主线的商品名；段落标题、正文、按钮、标签一律无衬线 |
| 消费者视图没有编号 | 不渲染 `01`/`02`；审计视图（16 区块）保留编号，因为那里确实是目录 |
| 用留白分段，不用发丝线 | 消费者主线段落之间靠间距，不靠 `border-bottom` 分隔；列表行去掉逐行虚线 |
| 少用大写字距标签 | `label-track` 不用于消费者主线的段落标题；小标题靠字号与字重区分 |
| 每屏只讲一件事 | 段落标题即问题：这是什么 / 里面有什么 / 谁做的 / 还有别的说法吗 |

## 与验收门禁的关系

`tests/acceptance_gates/test_consumer_readability.py` 把本文件的主要条款变成断言：
首屏零审计术语、三问可答、消费者视图无编号、衬线体只用于主标题与商品名、
到配料表的点击数上限。改文案时如果动了这些边界，先跑该门禁。
